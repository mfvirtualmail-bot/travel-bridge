The problem

Public WiFi almost always shows a login page first — a "captive portal" where you accept terms or enter a room number before you get online. A filtered device can't open that login page, so a filtered laptop or phone simply can't get onto the WiFi. The person is left feeling the only way out is to remove the filter — which it isn't.

How it works

A small, separate box — a Raspberry Pi with no screen and no keyboard — sits between the public WiFi and your device. It handles the login page once, then shares the connection over its own private WiFi.

A Raspberry Pi — the entire bridge. No screen, no keyboard: it just plugs into power.

Your filtered device

The key point: the filter is never touched, never disabled — not even for a second. The bridge deals only with the login page, which isn't content and which a filter can't render anyway. Every byte your device requests still goes through your filter (NetFree, TAG Lock, MB Smart, Gader, Gentech …) unchanged.

What it does & doesn't do

It does

  • Pass the WiFi login page for your device
  • Keep your device's filter filtering every byte
  • Work at airports, hotels and cafés
  • Run on cheap, off-the-shelf hardware

It does not

  • Disable, pause or weaken any filter
  • Act as a filter or replace one
  • Store, log or send your browsing anywhere
  • Let you browse on the Pi itself

Because the bridge carries raw packets (it has to, for the login page to work), it is a locked-down, non-browsable appliance — protected by a password, an optional hidden network name, and an optional list of exactly which devices may connect. Whether relying on such a separate bridge is appropriate is a question for a rav/posek; this page describes precisely what it does so that question can be asked accurately.

Two ways to build it

The installer auto-detects your hardware and picks the right mode.

ModeHardwareReliabilityNotes
Dual radio
recommended		 Built-in WiFi + a USB WiFi dongle High Built-in = hotspot, dongle = uplink. Any channel, more devices, full speed.
Single radio Built-in WiFi only Experimental One chip does both jobs on the same channel; ~5 devices; some 5 GHz networks can drop the hotspot. Good for trying the idea.

Get started

  1. Flash a Raspberry Pi with Raspberry Pi OS Bookworm (64-bit).
  2. Copy the pi/ folder over, set your hotspot name & password in travel-bridge.conf.
  3. Run sudo bash install.sh — it configures everything.
  4. Join a WiFi as the uplink, connect your device to the new hotspot, and browse.
